Pre-flight Checklist

Verificaciones antes de instalar cualquier cosa

⏱ ~10 min macOS 15+ Primera vez
ℹ️
Ejecutá todos estos comandos en Terminal.app antes de empezar. Si algo falla, preguntale a la AI.
🎓
¿Por qué hacer esto primero?
Antes de instalar cualquier herramienta, verificamos que el Mac esté en condiciones óptimas. Si instalás cosas sobre un sistema con poco espacio o incompatibilidades, los errores son difíciles de diagnosticar. Estos comandos te dan un "checkup" completo en 2 minutos.

✅ Lo que vas a verificar

  • Arquitectura del procesador (ARM64 = Apple Silicon ✓)
  • Espacio disponible en disco (mínimo 25 GB)
  • Versión de macOS (15+ recomendado)
  • Instalar Rosetta 2 para apps antiguas
  • Cifrado del disco activado

⚠️ Si algo falla

  • uname -m muestra x86_64 → usá el modo Rosetta, no es M5
  • Poco espacio → borrá descargas y vaciá Papelera primero
  • macOS desactualizado → ve a System Settings → General → Software Update

🍎 ¿Qué significa Apple Silicon M5?

El M5 es el procesador que diseñó Apple. La diferencia clave: es arquitectura ARM (como los procesadores de iPhone), no Intel x86_64. Esto importa porque:

✅ Ventajas ARM/M5

  • Compilaciones de código 3-4x más rápidas
  • Batería que dura 20+ horas bajo carga
  • Sin ventiladores en algunos modelos (silencioso)
  • AI local (Ollama) mucho más eficiente
  • La mayoría de herramientas ya tienen versión ARM nativa

⚠️ Lo que cambia para developers

  • Homebrew instala en /opt/homebrew/ (no /usr/local/)
  • Algunas imágenes Docker antiguas son solo x86 → usás Rosetta
  • Python/Node preinstalados son del sistema → no los toques
  • Siempre verificá que instalás la versión "arm64" o "Apple Silicon"
bash · pre-flight 
# ── Verificar arquitectura (debe decir arm64) ──
uname -m           # → arm64  (confirma Apple Silicon)
uname -r           # → versión del kernel macOS

# ── Verificar espacio disponible (necesitás ~25 GB) ──
df -h /            # columna "Avail" debe ser > 25G

# ── Instalar Rosetta 2 (para apps x86_64 legacy) ──
softwareupdate --install-rosetta --agree-to-license

# ── Verificar versión de macOS (15+ recomendado) ──
sw_vers

# ── Habilitar FileVault si no está activo (seguridad) ──
fdesetup status    # → "FileVault is On." es lo ideal

Xcode CLI Tools + Homebrew

La base de todo. Sin esto, nada más funciona.

⏱ ~15 min Obligatorio
🎓
¿Qué es Homebrew y por qué lo necesito?
En Windows tenés el instalador .exe. En Mac, los developers usan Homebrew — el "gestor de paquetes" universal. Con un solo comando brew install nombre-del-programa instalás cualquier herramienta sin buscar sitios web, sin instaladores gráficos, sin riesgo de descargar la versión equivocada. Es el primer paso obligatorio de cualquier Mac de desarrollo.

¿Y Xcode Command Line Tools?
macOS viene "limpio" sin compiladores de código. Las Xcode CLI Tools instalan el compilador C/C++, Make, Git básico, y las librerías del sistema que Homebrew y casi todo lo demás necesita internamente. Sin esto, el 80% de las instalaciones fallan silenciosamente.
⏱
Tiempo estimado: 10-15 minutos
Las Xcode CLI Tools son ~2GB. Homebrew tarda menos de 1 minuto. Necesitás conexión a internet y no cerrar la terminal durante la instalación.
bash · xcode + homebrew 
# ── Paso 1: Xcode Command Line Tools ──────────────────
xcode-select --install
# Aparece un diálogo gráfico → clic en "Install"
# Verificar cuando termine:
xcode-select -p   # → /Library/Developer/CommandLineTools

# ── Paso 2: Homebrew ──────────────────────────────────
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# ── Paso 3: Agregar brew al PATH (M1/M2/M3/M4/M5) ────
# Apple Silicon instala en /opt/homebrew (no /usr/local)
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

# ── Verificar instalación ─────────────────────────────
brew --version    # → Homebrew 4.x.x
brew doctor       # → Your system is ready to brew.

# ── Herramientas esenciales via brew ──────────────────
brew install curl wget git tree htop jq bat fd ripgrep fzf

🚀 Optimización de Homebrew

Si no estás seguro de qué paquetes instalar con Homebrew, prueba con brew search <keyword> para encontrar lo que necesitas, o revisa listas de herramientas recomendadas para desarrolladores en Mac.

📖 Cómo usar Homebrew — Comandos esenciales

bash · homebrew commands 
# ── Los 8 comandos de Homebrew que vas a usar siempre ─────────

brew install nombre       # instalar una herramienta CLI
brew install --cask nombre # instalar una app con interfaz gráfica (.app)
brew uninstall nombre      # desinstalar
brew upgrade               # actualizar TODO lo instalado
brew upgrade nombre        # actualizar solo un paquete
brew list                  # ver todo lo que instalaste
brew search nombre         # buscar si algo existe en Homebrew
brew info nombre           # ver versión, dependencias e info del paquete
brew doctor                # diagnosticar problemas con Homebrew
brew cleanup               # liberar espacio borrando versiones viejas

# ── Diferencia entre install y install --cask ─────────────────
# brew install git        → instala herramienta CLI (sin ícono en /Applications)
# brew install --cask cursor → instala app gráfica (crea ícono en /Applications)

# ── Ejemplo práctico: buscar e instalar curl ──────────────────
brew search curl           # busca "curl" → muestra paquetes disponibles
brew info curl             # muestra: versión 8.x.x, homepage, dependencias
brew install curl          # instala curl
curl --version             # verifica: curl 8.x.x (libcurl/8.x.x)
💡
Actualizar todo una vez por semana: Corré brew update && brew upgrade && brew cleanup los lunes para mantener todo actualizado. El && encadena comandos — si uno falla, los siguientes no corren.

Terminal Profesional · iTerm2 + Oh My Zsh

Tu terminal va a ser hermosa y productiva

⏱ ~25 min Recomendado
🎓
¿Por qué cambiar la terminal que ya viene en Mac?
La Terminal.app que viene con macOS funciona, pero es básica. iTerm2 agrega splits de pantalla, colores, perfiles, autocompletado visual y docenas de mejoras. Oh My Zsh es un framework que convierte tu shell en una herramienta poderosa: plugins para autocompletado, historial inteligente, detección del directorio git y mucho más. Powerlevel10k es el tema visual que muestra rama de Git, estado del directorio, hora y info relevante en el prompt — en milisegundos.

Como developer, vas a pasar horas en la terminal. Vale la pena tenerla configurada bien desde el principio.

📦 Qué se instala

  • iTerm2 — emulador de terminal avanzado
  • Oh My Zsh — framework para el shell Zsh
  • Powerlevel10k — tema visual con info de Git
  • zsh-autosuggestions — sugiere comandos del historial
  • zsh-syntax-highlighting — colorea comandos válidos/inválidos
  • zsh-z — navegar a carpetas frecuentes con solo escribir su nombre

🔑 Después de instalar

  • Abrí iTerm2 (no Terminal.app)
  • Se abrirá el wizard de Powerlevel10k — seguí los pasos visuales
  • Elegí la fuente MesloLGS NF en iTerm2 → Preferences → Profiles → Text
  • Reiniciá la terminal con exec zsh
⚠️
Error frecuente: "los íconos se ven como cuadrados"
Necesitás instalar la fuente MesloLGS NF y configurarla en iTerm2. El comando de instalación está incluido abajo. Si no lo hacés, verás caracteres extraños en el prompt.
bash · terminal setup 
# ── iTerm2 — el mejor emulador de terminal para Mac ──
brew install --cask iterm2

# ── Oh My Zsh — framework para Zsh ───────────────────
sh -c "$(curl -fsSL https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/tools/install.sh)"

# ── Powerlevel10k — el tema más popular ───────────────
git clone --depth=1 https://github.com/romkatv/powerlevel10k.git \
  ${ZSH_CUSTOM:-$HOME/.oh-my-zsh/custom}/themes/powerlevel10k

# En ~/.zshrc cambiar la línea ZSH_THEME:
# ZSH_THEME="powerlevel10k/powerlevel10k"
exec zsh  # reiniciar shell → wizard de configuración p10k

# ── Plugins esenciales ────────────────────────────────
git clone https://github.com/zsh-users/zsh-autosuggestions \
  ${ZSH_CUSTOM:-~/.oh-my-zsh/custom}/plugins/zsh-autosuggestions

git clone https://github.com/zsh-users/zsh-syntax-highlighting.git \
  ${ZSH_CUSTOM:-~/.oh-my-zsh/custom}/plugins/zsh-syntax-highlighting

git clone https://github.com/agkozak/zsh-z \
  ${ZSH_CUSTOM:-~/.oh-my-zsh/custom}/plugins/zsh-z

# En ~/.zshrc, agregar plugins:
# plugins=(git zsh-autosuggestions zsh-syntax-highlighting zsh-z)

# ── Fuentes Nerd Fonts (para iconos en terminal) ──────
brew tap homebrew/cask-fonts
brew install --cask font-meslo-lg-nerd-font
# En iTerm2: Profiles → Text → Font → MesloLGS NF

👻 Ghostty — La Terminal 2026

Terminal nativa escrita en Zig. Rápida, sin bloatware, sin IA forzada. La alternativa moderna a iTerm2 que ganó popularidad en 2025-2026. brew install --cask ghostty

🚀 Starship — Prompt Minimalista

Prompt escrito en Rust. Muestra git branch, lenguaje y versión de Node/Python/Go automáticamente. Alternativa liviana a Powerlevel10k. Instalá con brew install starship → agregá a ~/.zshrc: eval "$(starship init zsh)"

🔍 zoxide — cd Inteligente

Reemplazá cd con z: aprende tus carpetas más usadas y salta a ellas con un fragmento del nombre. brew install zoxide → eval "$(zoxide init zsh)"

ℹ️
Ghostty vs iTerm2: Ghostty es la apuesta 2026 — más rápida y sin dependencias pesadas. iTerm2 sigue siendo válida si ya tenés profiles, scripts y configuraciones que no querés migrar.

⚡ .zshrc — Tu archivo de configuración

El archivo ~/.zshrc se ejecuta cada vez que abrís una terminal. Es donde guardás tus atajos, configuraciones y variables. El ~ significa "tu carpeta home".

bash · .zshrc recomendado 
# ── Abrir el .zshrc en VS Code para editar ────────────────────
code ~/.zshrc

# ══════════════════════════════════════════════════════════════
# CONTENIDO RECOMENDADO PARA TU ~/.zshrc
# Copiar y pegar al final del archivo, luego guardar
# ══════════════════════════════════════════════════════════════

# ── Navegación más rápida ─────────────────────────────────────
alias ls="eza --icons"         # ls con íconos y colores
alias ll="eza -la --icons"    # lista detallada con ocultos
alias lt="eza --tree --level=2" # árbol de directorios
alias cat="bat"               # cat con syntax highlighting
alias ..="cd .."              # subir un directorio
alias ...="cd ../.."          # subir dos directorios
alias ~="cd ~"               # ir al home

# ── Git shortcuts ─────────────────────────────────────────────
alias gs="git status"
alias ga="git add ."
alias gc="git commit -m"
alias gp="git push"
alias gl="git log --oneline --graph --decorate"
alias gco="git checkout"
alias gnb="git checkout -b"  # crear nueva rama

# ── Node / npm shortcuts ──────────────────────────────────────
alias ni="npm install"
alias nr="npm run"
alias nrd="npm run dev"
alias nrb="npm run build"

# ── Docker shortcuts ──────────────────────────────────────────
alias dc="docker compose"
alias dcu="docker compose up -d"
alias dcd="docker compose down"
alias dcl="docker compose logs -f"  # ver logs en tiempo real

# ── Funciones útiles ──────────────────────────────────────────
# mkcd: crear carpeta y entrar a ella en un comando
mkcd() { mkdir -p "$1" && cd "$1"; }

# port: ver qué proceso usa un puerto
port() { lsof -i :"$1"; }

# kilport: matar proceso en un puerto
killport() { kill -9 $(lsof -t -i:"$1"); }

# ── Aplicar cambios sin cerrar la terminal ────────────────────
# Después de editar .zshrc, correr:
source ~/.zshrc   # recarga la configuración

Git + GitHub CLI

Configuración profesional de Git y autenticación

⏱ ~15 min
🎓
¿Qué es Git y por qué es tan importante?
Git es el sistema de control de versiones que usa el 95% de los developers del mundo. Imaginaló como un "historial de cambios con viaje en el tiempo" para tu código. Con Git podés: ver qué cambió en cada archivo, volver a cualquier punto anterior, trabajar en paralelo con otros developers sin pisarse, y mantener un historial completo de todo lo que hiciste.

GitHub es el servicio en la nube donde se guardan los repositorios Git. GitHub CLI (gh) te permite hacer todo desde la terminal sin abrir el navegador — crear repos, abrir pull requests, revisar issues.

SSH keys: en lugar de escribir usuario y contraseña cada vez que hacés push/pull, usás un par de llaves criptográficas. La privada queda en tu Mac, la pública va a GitHub. Más seguro y más cómodo.
bash · git config 
# ── Instalar última versión de Git via Homebrew ───────
brew install git
git --version

# ── Configuración global ──────────────────────────────
git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"
git config --global init.defaultBranch main
git config --global pull.rebase false
git config --global core.editor "code --wait"

# ── SSH Key para GitHub (más seguro que HTTPS) ────────
ssh-keygen -t ed25519 -C "tu@email.com"
eval "$(ssh-agent -s)"
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
pbcopy < ~/.ssh/id_ed25519.pub
# Ir a github.com → Settings → SSH Keys → New SSH Key → pegar
ssh -T git@github.com  # → Hi username! You've successfully authenticated

# ── GitHub CLI ────────────────────────────────────────
brew install gh
gh auth login   # autenticación interactiva via browser
gh status        # verificar conexión

# ── Aliases útiles de Git ─────────────────────────────
git config --global alias.st status
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.lg "log --oneline --graph --decorate"

📖 Flujo de trabajo Git para principiantes

El flujo diario de trabajo con Git tiene 5 comandos que vas a usar todo el tiempo. Memorizalos y el resto viene solo.

bash · git daily workflow 
━━━ CREAR UN PROYECTO NUEVO ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
mkdir mi-proyecto && cd mi-proyecto
git init               # inicializa repositorio Git en esta carpeta
gh repo create mi-proyecto --public --source=. --push
# ↑ crea el repo en GitHub y sube el código en un solo comando

━━━ FLUJO DIARIO (5 comandos) ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
git status             # ver qué archivos cambiaron
git add .              # marcar TODOS los cambios para guardar
git add archivo.js     # marcar solo un archivo específico
git commit -m "mensaje" # guardar los cambios con descripción
git push               # subir al repositorio en GitHub
git pull               # traer cambios del repositorio remoto

━━━ RAMAS (BRANCHES) — trabajar en features sin romper main ━━━━━━━━
git checkout -b nueva-feature  # crear y cambiar a nueva rama
git branch                     # ver en qué rama estás
git checkout main              # volver a la rama principal
git merge nueva-feature        # traer los cambios a main

━━━ DESHACER ERRORES ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
git restore archivo.js     # descartar cambios en un archivo (CUIDADO: irreversible)
git stash                  # guardar cambios temporalmente sin commitear
git stash pop              # recuperar cambios del stash
git log --oneline          # ver historial de commits

━━━ .gitignore — archivos que Git NO debe guardar ━━━━━━━━━━━━━━━━━━━
echo "node_modules/" >> .gitignore   # nunca subir las dependencias
echo ".env" >> .gitignore            # NUNCA subir contraseñas/keys
echo ".DS_Store" >> .gitignore       # basura de Mac
🚨
NUNCA hagas push de un .env con contraseñas o API keys. Si accidentalmente lo subiste, considerá esas keys comprometidas — cambialas inmediatamente. GitHub escanea repos públicos buscando keys y las desactiva automáticamente. Siempre agregá .env al .gitignore antes del primer commit.

Lenguajes de Programación

Node, Python, Go, Rust, Java, Ruby — todos con gestores de versiones

⏱ ~40 min Instalá solo los que usás
🎓
¿Por qué usar gestores de versiones en lugar de instalar directo?
El problema con instalar Node.js o Python "directo" es que un día un proyecto va a necesitar Node 18, y otro Node 22. Con los gestores de versiones (nvm para Node, pyenv para Python, rbenv para Ruby, SDKMAN para Java) podés tener múltiples versiones instaladas y cambiar entre ellas con un comando. Esto es estándar en cualquier entorno profesional.

Instalá solo los lenguajes que vas a usar. No hay que instalar todos — si tu stack es Node + Python, skip Java y Ruby.

🔵 Node.js — Frontend / Backend JS

Imprescindible para React, Next.js, Vue, Express, y cualquier proyecto JS/TS. nvm te permite tener Node 18, 20 y 22 instalados simultáneamente.

🟡 Python — Data Science / AI / Backend

El lenguaje más usado en AI/ML. pyenv evita conflictos con el Python del sistema (que macOS usa internamente — no tocarlo).

🔵 Go — Backend de alto rendimiento

Lenguaje de Google. Ideal para APIs, microservicios y herramientas CLI. Compila a binario nativo — muy rápido en Apple Silicon.

🟠 Rust — Sistemas y rendimiento extremo

El lenguaje de moda para herramientas de desarrollo. Muchas herramientas modernas (ripgrep, bat, eza) están escritas en Rust.

bash · node + python + go + rust 
━━━ NODE.JS — con nvm (Node Version Manager) ━━━━━━━━━━━━━━━━
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
source ~/.zshrc
nvm install --lts        # Node.js LTS más reciente (22.x)
nvm use --lts
nvm alias default node
node --version && npm --version
npm install -g pnpm yarn tsx nodemon  # package managers + herramientas

━━━ PYTHON — con pyenv ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
brew install pyenv
echo 'export PYENV_ROOT="$HOME/.pyenv"' >> ~/.zshrc
echo 'eval "$(pyenv init -)"' >> ~/.zshrc
source ~/.zshrc
pyenv install 3.13.0
pyenv global 3.13.0
pip install --upgrade pip uv poetry   # uv = pip ultra-rápido

━━━ GO ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
brew install go
go version
echo 'export GOPATH=$HOME/go' >> ~/.zshrc
echo 'export PATH=$PATH:$GOPATH/bin' >> ~/.zshrc

━━━ RUST ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source ~/.cargo/env
rustc --version && cargo --version

━━━ JAVA — con SDKMAN ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 21.0.5-tem   # Temurin LTS
sdk install maven gradle

━━━ RUBY — con rbenv ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
brew install rbenv ruby-build
rbenv install 3.4.2
rbenv global 3.4.2

Docker + Kubernetes

Contenedores y orquestación para desarrollo local

⏱ ~20 min Recomendado
🎓
¿Qué es Docker y por qué lo necesitan todos los developers?
Docker te permite "empaquetar" una aplicación con todas sus dependencias en un contenedor — como una caja sellada que funciona igual en cualquier máquina. El problema clásico del desarrollo es "en mi máquina funciona" — con Docker, si funciona en tu contenedor, funciona en producción.

Casos de uso inmediatos para vos:
• Correr bases de datos (PostgreSQL, Redis) sin instalarlas en el sistema
• Levantar proyectos de otros developers con un solo comando
• Aislar dependencias de distintos proyectos
• Simular el entorno de producción localmente

Kubernetes (K8s) es para orquestar múltiples contenedores en producción — lo usás cuando tu app crece. Para empezar, enfocate en Docker.

🐳 Docker en la práctica

El comando más útil: docker compose up — levanta todos los servicios de un proyecto (app + DB + cache) en segundos.

☸️ Kubernetes — ¿cuándo lo necesito?

Cuando tenés múltiples servicios en producción y necesitás auto-scaling, alta disponibilidad y rolling updates. Para proyectos personales: opcional.

💻
Docker Desktop en Apple Silicon
Docker Desktop usa virtualización ligera en Mac. En M5 es muy eficiente — mucho mejor que en versiones anteriores. Asegurate de habilitarlo en Settings → General → Use Virtualization Framework y activar VirtioFS para máxima velocidad de I/O.

# Guardar en la raíz del proyecto
# Usar con: docker compose up -d

version: '3.9'

services:

  ## ── Base de datos PostgreSQL ──────────────────────────────────
  db:
    image: postgres:17
    environment:
      POSTGRES_USER: dev
      POSTGRES_PASSWORD: dev123     # solo para desarrollo local
      POSTGRES_DB: mi_app
    ports:
      - "5432:5432"                  # accesible en localhost:5432
    volumes:
      - pgdata:/var/lib/postgresql/data  # los datos persisten al reiniciar

  ## ── Cache Redis ───────────────────────────────────────────────
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

  ## ── Tu aplicación (si es Node.js) ─────────────────────────────
  app:
    build: .                           # busca Dockerfile en el directorio actual
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgresql://dev:dev123@db:5432/mi_app
      REDIS_URL: redis://redis:6379
    depends_on:
      - db
      - redis

volumes:
  pgdata:                              # volumen persistente para PostgreSQL

Bases de Datos

PostgreSQL, MySQL, Redis, MongoDB

⏱ ~20 min
🎓
¿Qué base de datos necesito?
Depende de tu proyecto. Guía rápida:
• PostgreSQL — la más recomendada para proyectos nuevos. Relacional, robusta, gratuita, usada por Supabase, Railway y la mayoría de los cloud providers. Si no sabés qué elegir, elegí Postgres.
• MySQL — alternativa a PostgreSQL. Popular en proyectos legacy y WordPress.
• Redis — base de datos en memoria. Se usa para cache, sesiones, colas de trabajo. No reemplaza a PostgreSQL — las complementa.
• MongoDB — base de datos de documentos (JSON). Buena para datos no estructurados y prototipos rápidos.

Recomendación para empezar: instalá solo PostgreSQL + Redis. Son los más usados en proyectos modernos.
💡
Tip: Usá Docker para las bases de datos
En lugar de instalar PostgreSQL en el sistema, podés correrla en Docker: docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=postgres postgres:17. Esto mantiene el sistema más limpio y podés levantar/bajar la DB con un comando.

¿Por qué "reemplazar" ls, cat y grep?
Los comandos básicos de Unix son de los años 70. Ollama Stack Offline

IA local: Ollama + Open WebUI — $0, sin internet, privado

⏱ ~20 min M5 Optimizado
🎓
¿Por qué correr AI localmente si hay ChatGPT y Claude online?
Tres razones concretas:
1. Privacidad — tu código nunca sale de tu Mac. Para proyectos con datos sensibles o NDA es importante.
2. Costo $0 — sin límites de tokens, sin factura mensual. Una vez descargado el modelo, funciona sin internet para siempre.
3. El M5 es excepcionalmente bueno para esto — la Unified Memory Architecture de Apple Silicon comparte RAM entre CPU y GPU. Un Mac con 24GB puede correr modelos de 14B parámetros que en PC necesitarían una GPU de $1500+.

Errores Comunes y Soluciones

Los 15 errores más frecuentes al configurar un Mac de desarrollo — con solución exacta

Referencia rápida Consultá cuando algo falla

❌ "command not found: brew"

Homebrew está instalado pero no en el PATH. Correr:

echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile && source ~/.zprofile

❌ "xcrun: error: invalid active developer path"

Las Xcode CLI Tools se desinstalaron después de una actualización de macOS.

xcode-select --install

❌ "EACCES: permission denied" en npm install -g

El npm global no tiene permisos. Solución: usar nvm (que ya instalaste) en lugar del npm del sistema.

nvm use --lts && npm install -g nombre-paquete

❌ "docker: Cannot connect to Docker daemon"

Docker Desktop no está corriendo.

open -a Docker # abrí Docker Desktop y esperá el ícono en la barra de menú

❌ "Port 3000 is already in use"

Hay un proceso usando ese puerto. Ver cuál y matarlo:

lsof -i :3000
kill -9 $(lsof -t -i:3000)

❌ "python: command not found" (solo python3 funciona)

En macOS moderno, el ejecutable se llama python3. Crear alias:

echo 'alias python="python3"' >> ~/.zshrc && source ~/.zshrc

❌ "zsh: command not found: code" (VS Code)

El comando code no está en el PATH. Abrir VS Code → Cmd+Shift+P → "Shell Command: Install 'code' command in PATH"

❌ Ollama dice "CPU" en vez de "GPU"

Si instalaste via .dmg (app), las variables de entorno en .zshrc no aplican. Usar launchctl:

launchctl setenv OLLAMA_FLASH_ATTENTION 1
launchctl setenv OLLAMA_KV_CACHE_TYPE q8_0
# Reiniciar Ollama desde el ícono del menú bar

❌ git push falla: "Authentication failed"

GitHub ya no acepta contraseñas por HTTPS. Usar SSH (ya configurado en Fase 3) o autenticarse con GitHub CLI:

gh auth login # sigue los pasos en el browser

❌ "The authenticity of host can't be established" (SSH)

Primera vez que conectás a GitHub por SSH. Escribir "yes" — es normal y esperado la primera vez.
