Visión General

Qué es TutoApp y cómo están organizadas sus capas

TutoApp es una suite de guías interactivas que combinan documentación técnica estática (HTML + CSS + JS) con un asistente AI integrado que puede responder preguntas, agregar contenido y mejorar secciones en tiempo real. El sistema está diseñado para correr completamente en local — sin servidor externo, sin cuenta, sin suscripción.

📄 Capa Frontend

5 archivos HTML auto-contenidos. Cada uno incluye el CSS, el JS y la lógica de AI integrada. Se sirven desde localhost:8000 via FastAPI StaticFiles.

⚙️ Capa Backend

FastAPI en server/main.py. Un solo archivo. Proxea las llamadas a Claude/Gemini/Ollama manteniendo las API keys fuera del browser.

🔑 Capa de Configuración

Archivo server/.env con las API keys del usuario. Nunca va a Git. El backend lo lee al iniciar via python-dotenv.

💡
Diseño sin servidor externo: TutoApp usa Puter.js como proveedor default — una librería que conecta con modelos AI gratuitos sin necesidad de API key. El backend FastAPI solo entra en juego cuando el usuario quiere usar Claude o Gemini con su propia key.

Flujo de Datos

Qué pasa exactamente cuando el usuario hace una pregunta al asistente AI

Flujo con Puter.js (sin backend)

Cuando el proveedor activo es Puter, el HTML llama directamente a la API de Puter sin pasar por el backend local:

[Browser / HTML] │ │ puter.ai.chat(messages, { model, stream: true }) │ ▼ [Puter.js CDN] │ │ Reenvía al modelo AI seleccionado (Gemini / GPT / Claude) │ ▼ [Modelo AI Externo] │ │ Respuesta en streaming → AsyncIterator de chunks │ ▼ [Browser] # onToken(chunk) llamado por cada fragmento recibido

Flujo con Claude/Gemini (via backend local)

Cuando el proveedor necesita API key propia, el HTML envía el request al backend FastAPI local que lo reenvía a la API externa con la key del .env:

[Browser / HTML] │ │ fetch("http://localhost:8000/api/claude", { method: 'POST', body: payload }) │ ▼ [FastAPI / main.py] │ │ Lee ANTHROPIC_API_KEY del .env │ httpx.AsyncClient().stream("POST", anthropic_url, headers={x-api-key: KEY}) │ ▼ [Anthropic / Google / Ollama] │ │ StreamingResponse — bytes en tiempo real via SSE │ ▼ [FastAPI] # aiter_bytes() reenvía el stream sin buffering │ ▼ [Browser] # ReadableStream → onToken() por cada chunk
🔑
Por qué el proxy: Las API keys de Claude y Gemini no pueden estar en el código del browser — cualquier persona que abra DevTools las vería. El backend las guarda en .env (que nunca va a Git) y las inyecta en cada request del servidor.

Flujo de Datos: Integración de Proveedores AI

TutoApp maneja la comunicación con diferentes proveedores de IA de forma optimizada y segura. La arquitectura diferencia entre proveedores que pueden ser llamados directamente desde el frontend (sin keys sensibles) y aquellos que requieren un proxy backend para proteger las claves de API.

1. Flujo Directo con Puter.js (Frontend Puro)

Para proveedores como Puter.js, que ofrecen una integración simplificada a través de su CDN y no exponen claves de API críticas en cada llamada, el flujo es más liviano:

[Browser / HTML & Vanilla JS] │ │ A. El JS en `client/main.js` llama a `puter.ai.chat(...)` │ # Usando la librería JS de Puter.js │ ▼ [Puter.js CDN (External)] │ │ B. Puter.js se comunica con el modelo seleccionado (ej. Gemini, Claude, etc.) │ C. Recibe la respuesta en streaming como un AsyncIterator │ ▼ [Browser / JS Callback] │ │ D. El callback `onToken(chunk)` es invocado por Puter.js por cada fragmento recibido │ # Actualiza la UI de TutoApp en tiempo real │ ▼ [UI Renderizada]

Ventaja: Menos latencia al evitar el round-trip al backend local. Ideal para demos o cuando la seguridad de la clave no es una preocupación primordial (como con Puter.js).

2. Flujo Proxy con Backend FastAPI (Claude, Gemini, Ollama)

Cuando se utilizan proveedores que requieren claves de API (ej. Anthropic, Google AI) o servicios que se ejecutan localmente pero necesitan una capa de abstracción (ej. Ollama), TutoApp emplea un proxy backend. Esto es fundamental para la seguridad y la gestión centralizada de las configuraciones.

[Browser / HTML & Vanilla JS] │ │ A. El JS en `client/main.js` realiza un `fetch` al endpoint del backend │ # Ejemplo: fetch("/api/gemini", { method: 'POST', body: JSON.stringify({ prompt: "..." }) }) │ ▼ [FastAPI Server (`main.py`)] │ │ B. El endpoint (ej. `/api/gemini`) recibe el request │ C. Lee la API key correspondiente desde el archivo `.env` (e.g., `GEMINI_API_KEY`) │ # `python-dotenv` carga las variables de entorno │ D. Utiliza `httpx.AsyncClient` para reenviar el request al proveedor AI externo │ # `headers` incluyen la clave de API; `body` contiene el prompt/payload │ ▼ [Proveedor AI Externo (Google, Anthropic, etc.) / Ollama Local] │ │ E. El proveedor procesa la solicitud y devuelve la respuesta en streaming. │ # TutoApp usa `stream=True` en `httpx` para recibir chunks sin esperar el final. │ ▼ [FastAPI Streaming Response] │ │ F. El backend recibe los chunks de datos del proveedor. │ G. Utiliza `StreamingResponse` para enviar los chunks al cliente (browser) en tiempo real. │ # `stream_with_generator` y `httpx` `aiter_bytes()` son claves aquí para evitar buffering. │ ▼ [Browser / JS EventSource / ReadableStream] │ │ H. El `fetch` en el frontend recibe los chunks como un stream. │ I. El manejador `onmessage` o `onToken(chunk)` procesa cada fragmento recibido │ # Actualiza la UI de TutoApp dinámicamente │ ▼ [UI Renderizada]
🔑
El Rol Crucial del Proxy Backend: Las claves de API (como `ANTHROPIC_API_KEY` o `GEMINI_API_KEY`) **nunca** deben exponerse en el código del frontend (HTML/JS). Si estuvieran allí, cualquiera podría verlas en las herramientas de desarrollador del navegador. El backend de TutoApp (`main.py`) actúa como un intermediario seguro:
  1. Lee las claves de un archivo `.env` local (que está listado en `.gitignore` y nunca se sube a control de versiones).
  2. Reenvía las solicitudes del navegador a las APIs externas, inyectando la clave de API secreta desde el lado del servidor.
  3. Maneja las respuestas en streaming, permitiendo una experiencia de usuario fluida sin largas esperas.
Esto mantiene tus credenciales seguras y tu aplicación funcionando correctamente.

3. Flujo con Ollama (Proxy Local Opcional)

Aunque Ollama corre localmente, TutoApp usa un endpoint proxy dedicado (`/api/ollama`) en FastAPI. Esto permite centralizar la lógica de red, aplicar posibles transformaciones o logs, y mantener una interfaz consistente con otros proveedores que sí requieren proxy.

[Browser / HTML & Vanilla JS] │ │ A. `fetch("/api/ollama", { method: 'POST', body: payload })` │ ▼ [FastAPI Server (`main.py`)] │ │ B. Llama a `http://localhost:11434` (la URL por defecto de Ollama) │ # El `request.url.hostname` en FastAPI se resuelve a localhost │ ▼ [Ollama Server (Local)] │ │ C. Ollama procesa la solicitud y responde en streaming. │ ▼ [FastAPI Streaming Response] │ │ D. FastAPI reenvía el stream al navegador. │ ▼ [Browser / JS] │ │ E. El JS consume el stream y actualiza la UI. │ ▼ [UI Renderizada]

Nota: El proxy para Ollama es más por consistencia y manejo centralizado que por necesidad de seguridad de claves (ya que Ollama no usa claves de API de la misma forma que los servicios cloud).

POST /api/gemini Proxy a Google Gemini API

Similar a Claude, este endpoint toma el body de la API de Gemini (contents, generationConfig, etc.) y añade la API key desde el .env en el header x-api-key. Devuelve la respuesta JSON de Gemini.

code 
# server/main.py — ejemplo simplificado para Gemini
from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import StreamingResponse
import httpx
import os

# ... (otras importaciones y setup)

# Asumiendo que tienes una función para cargar la API key del .env
def get_gemini_key():
    return os.getenv("GEMINI_API_KEY")

gemini_client = httpx.AsyncClient() # Cliente HTTP asíncrono
async def proxy_gemini(request: Request):
    if not get_gemini_key():
        raise HTTPException(status_code=400, detail="Gemini API Key not configured")
    
    json_data = await request.json()
    headers = {
        "x-goog-api-key": get_gemini_key(),
        "Content-Type": "application/json"
    }
    
    # URL de la API de Gemini
    url = "https://generativelanguage.googleapis.com/v1beta/models/gemini-pro:generateContent"
    
    try:
        # Realiza la petición a la API de Gemini
        response = await gemini_client.post(url, json=json_data, headers=headers)
        response.raise_for_status() # Lanza excepción para errores HTTP (4xx, 5xx)
        
        return response.json() # Devuelve la respuesta JSON
        
    except httpx.HTTPStatusError as e:
        raise HTTPException(status_code=e.response.status_code, detail=e.response.text)
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

# Registrar el endpoint en la app FastAPI
app.add_api_route("/api/gemini", proxy_gemini, methods=["POST"])
POST /api/ollama Proxy a Ollama local (localhost:11434)

Este endpoint es un proxy directo a tu instancia local de Ollama. Dado que Ollama no requiere una API key para ser accedido localmente, este proxy simplemente reenvía las peticiones (típicamente a /api/generate o /api/chat) y devuelve la respuesta. Es crucial que Ollama esté corriendo en localhost:11434.

code 
# server/main.py — ejemplo simplificado para Ollama
from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import StreamingResponse
import httpx

# ... (otras importaciones y setup)

ollama_client = httpx.AsyncClient(base_url="http://localhost:11434") # Cliente configurado para Ollama

async def proxy_ollama(request: Request):
    # Extraer el path y la query de la request original
    path = request.url.path.replace("/api/ollama", "") # Elimina el prefijo /api/ollama
    url = httpx.URL(path=path, query=request.url.query.encode("utf-8"))
    
    json_data = await request.json()
    
    # Reenvía la petición a Ollama
    try:
        # Usamos stream=True para obtener un iterador de chunks
        req = ollama_client.build_request(
            request.method, url, json=json_data, headers=request.headers,
            params=request.query_params
        )
        prepped = await ollama_client.prepare_request(req)
        # Si la petición original era SSE, mantenemos el stream
        is_stream = request.headers.get("accept", "").find("text/event-stream") != -1
        
        rp = await ollama_client.send(prepped, stream=is_stream)
        
        if is_stream:
            # Si es stream, devolvemos un StreamingResponse
            async def iter_stream():
                async for chunk in rp.aiter_bytes():
                    yield chunk
            return StreamingResponse(iter_stream(), media_type=rp.headers["content-type"])
        else:
            # Si no es stream, devolvemos la respuesta JSON
            return rp.json()

    except httpx.RequestError as e:
        raise HTTPException(status_code=504, detail=f"Ollama is unreachable: {e}")
    except httpx.HTTPStatusError as e:
        raise HTTPException(status_code=e.response.status_code, detail=e.response.text)
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

# Registrar el endpoint en la app FastAPI
# Permitimos cualquier subpath bajo /api/ollama para flexibilidad
app.add_api_route("/api/ollama/{path:path}", proxy_ollama, methods=["POST", "GET", "PUT", "DELETE", "PATCH", "OPTIONS"])
POST /api/save-section Persistencia de contenido AI en HTML

Este endpoint es el mecanismo de guardado. Recibe un objeto JSON con file (el nombre del archivo HTML, ej. index.html) y content (el nuevo HTML a insertar). Utiliza una whitelist (_ALLOWED_FILES) para prevenir escrituras arbitrarias en el sistema de archivos. El contenido se inserta dentro de un tag específico con un ID para facilitar su localización.

code 
# server/main.py — función save_section
from fastapi import FastAPI, Request, HTTPException, Depends
from fastapi.responses import JSONResponse
import os
import re

# Whitelist de archivos permitidos para escritura
_ALLOWED_FILES = {"index.html", "backend.html", "frontend.html", "providers.html", "run.html"}

async def save_section(request: Request):
    try:
        data = await request.json()
        filename = data.get("file")
        content = data.get("content")
        section_id = data.get("section_id") # ej. "backend"

        if not filename or not content or not section_id:
            raise HTTPException(status_code=400, detail="Missing file, content, or section_id")
        
        if filename not in _ALLOWED_FILES:
            raise HTTPException(status_code=403, detail=f"File not allowed: {filename}")

        filepath = os.path.join("client", filename)
        
        with open(filepath, 'r', encoding='utf-8') as f:
            html_content = f.read()
            
        # Patrón para encontrar la sección a reemplazar
        # Busca un tag div con el ID dado, y reemplaza su contenido interno
        pattern = re.compile(ff'
.*?
', re.DOTALL)
        
        # Creamos el nuevo div con el contenido generado por AI
        new_section_html = ff'
{content}
'
        
        # Reemplazamos la sección antigua con la nueva
        new_html_content, num_replacements = pattern.subn(new_section_html, html_content)
        
        if num_replacements == 0:
             # Si no se encontró la sección, podrías insertarla al final o lanzar error
             # Aquí, optamos por lanzar un error para indicar un problema de template
            raise HTTPException(status_code=404, detail=f"Section ID '{section_id}' not found in {filename}")

        with open(filepath, 'w', encoding='utf-8') as f:
            f.write(new_html_content)
            
        return JSONResponse(content={"message": "Section saved successfully"})
        
    except HTTPException as e:
        raise e
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

# Registrar el endpoint en la app FastAPI
app.add_api_route("/api/save-section", save_section, methods=["POST"])

FastAPI como Orquestador

FastAPI actúa como el "director de orquesta" de TutoApp. No genera contenido AI directamente, sino que coordina las solicitudes del frontend (los HTMLs) hacia los diferentes proveedores de AI (Claude, Gemini, Ollama) y maneja la persistencia de los resultados. Su ligereza y enfoque en la API (ASGI) lo hacen ideal para este rol.

Python y Arquitectura

El uso de Python con FastAPI permite una rápida iteración y prototipado. La arquitectura es deliberadamente simple: un backend minimalista (sin base de datos ni ORM) que expone APIs para interactuar con servicios externos (AI) y para manejar la lógica de persistencia de datos (guardar HTML). Las dependencias son mínimas (FastAPI, Uvicorn, httpx, python-dotenv), lo que facilita el despliegue y la gestión.

start.bat — El lanzador Windows

El lanzador automatiza todo el setup para usuarios no técnicos. Está escrito en ASCII puro (sin caracteres Unicode) para evitar errores de encoding en CMD:

Lo que hace start.bat

  • Verifica que Python está en el PATH
  • Crea server/.venv si no existe
  • Instala requirements solo si falta uvicorn.exe
  • Crea .env desde .env.example si no existe
  • Libera el puerto 8000 si está ocupado
  • Muestra el menú de guías con choice
  • Arranca uvicorn en ventana minimizada
  • Espera que el servidor responda en /api/health
  • Abre el browser en la guía elegida

Decisiones técnicas

  • choice /C 012345 en lugar de set /p — no requiere Enter, más confiable
  • ERRORLEVEL capturado inmediatamente en variable — se sobreescribe con cada comando
  • if not exist uvicorn.exe — evita pip en cada arranque
  • PowerShell para liberar puerto — más robusto que parsear netstat
  • curl con --max-time 2 para polling — timeout corto, hasta 30 intentos

🔑 API keys fuera del browser

Las keys de Claude y Gemini nunca tocan el código del browser. Viven en server/.env (excluido de Git) y el backend las inyecta en cada request. La key nunca aparece en DevTools → Network.

Para Puter, Grok y Gemini directo: el usuario guarda sus propias keys en localStorage del browser — son suyas y nunca salen de su dispositivo.

⚠️
Límite de seguridad: TutoApp está diseñado para uso local en tu propia máquina, no como servicio público. El CORS está abierto (allow_origins=["*"]) porque solo corre en localhost. No expongas el puerto 8000 a internet sin agregar autenticación.

FAQ Técnico

Las preguntas más frecuentes sobre cómo funciona el sistema

¿Qué pasa si agrego un nuevo archivo HTML al proyecto?

Tenés que hacer dos cosas: (1) agregar el filename al set _ALLOWED_FILES en server/main.py para que /api/save-section lo acepte, y (2) agregar una opción al menú de start.bat si querés que sea accesible desde el lanzador.

¿Por qué el backend usa httpx y no requests?

requests es síncrono — bloquearía el event loop de uvicorn mientras espera la respuesta de Anthropic (que puede tardar 30+ segundos en completar). httpx tiene soporte async nativo y soporte de streaming via client.stream() + aiter_bytes().

¿Por qué el StaticFiles de FastAPI va al FINAL del archivo?

FastAPI evalúa los middleware y rutas en orden de registro. Si el app.mount("/") del StaticFiles estuviera al principio, capturaría todos los requests incluyendo /api/health, /api/claude, etc., devolviendo 404 para todos. Al ir al final, las rutas /api/* tienen prioridad.

¿Cómo funciona el fallback de modelos en Puter.js?

La función callPuter() en los HTMLs tiene una lista PUTER_FALLBACK_MODELS y prueba los modelos en orden hasta que uno responda sin error "model not found". Si el error es de autenticación (sign, auth, login), propaga inmediatamente sin probar los demás — ya que el mismo error ocurriría para todos.
